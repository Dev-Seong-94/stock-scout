# 구현 계획: 싸 보이는 후보 찾기 → 근거 확인

스펙: [docs/specs/value-evidence.md](../docs/specs/value-evidence.md)
작업 목록: [tasks/todo.md](todo.md)

## 개요

조건 계산을 순수 함수 하나로 모아, 종목 페이지와 스크리너가 같은 결과를 쓰게 해요.
먼저 종목 페이지의 "싼가?"를 끝까지 연결하고, 스크리너, "왜 떨어졌나?", 전체 재생성 순서로 진행해요.

## 설계 결정

- **계산은 `app/cheapness.py` 한곳에서 해요.** 스크리너 개수와 "싼가?" 세 줄이 어긋나지 않게 하는 핵심이에요.
- **세 조건은 모두 스냅샷 값으로 계산해요.** 종목 페이지의 실시간 카드와 숫자가 다를 수 있어서 블록에 기준 날짜를 적어요.
- **자기 과거 조건은 PER의 기준을 맞춰요.** 현재값과 중앙값 모두 `valuation_ranges`의 직전 회계연도 기준을 써요.
  최근 12개월 PER과 연간 기준 중앙값을 비교하면 실적이 빠르게 변하는 회사에서 잘못된 결과가 나와요.
  그래서 "업종 대비" 줄의 PER(최근 12개월)과 숫자가 다를 수 있고, 줄마다 기준을 적어요.
- **주간 가격으로 계산해요.** 스냅샷은 일간 가격을 받으므로, 종목 페이지와 같도록 주간으로 줄인 뒤 `valuation_ranges`에 넘겨요.
- **새 지표 2개를 `metrics.py`에 정의해요.** `pe_vs_own`(자기 중앙값 대비 %), `cash_value_gap`(기본 계산값 대비 현재가 %)이에요.
  필터로도 쓸 수 있고, 지표 목록은 38개에서 40개가 돼요.
- **개수는 지표가 아니라 스크리너 내부 열이에요.** `cheap_met`, `cheap_checkable`은 필터나 섹터 백분위 대상이 아니라서 `metrics.py`에 넣지 않아요.
- **시작 버튼은 거르지 않고 정렬만 해요.** "내 기준은 거르지 않는다"는 기존 결정과 같아요. 표 위에 "3개 모두 충족 N개"를 보여 줘요.
- **"왜 떨어졌나?"는 별도 API로 받아요.** 분기 실적과 ETF 가격은 느릴 수 있어서, 늦어도 나머지 화면을 막지 않아요.

## 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 가격을 5년으로 늘리면 52주 고점 등 기존 지표가 바뀔 수 있어요 | 높음 | `price_indicators`에는 최근 2년만 넘기고, 2년과 5년 결과가 같다는 테스트를 추가해요 |
| 소량 테스트 빌드가 실제 스냅샷을 덮어써요 | 높음 | `--limit`을 쓰지 않아요. 네트워크 확인은 파일을 쓰지 않는 `build_row` 호출로 해요 |
| 재생성 도중 실패하거나 Yahoo가 요청을 제한해요 | 중간 | 재생성 전에 기존 파일을 백업해요. 25개마다 체크포인트가 있고 이어서 돌릴 수 있어요 |
| 일괄 다운로드가 커져서 실패가 늘어요 | 중간 | `snapshot_meta.json`의 `no_prices`를 재생성 전후로 비교해요 |
| 재생성 전 스냅샷에 새 열이 없어요 | 중간 | 자기 과거 조건은 "다시 만들면 볼 수 있어요"로 표시하고, 기존 `skipped` 안내도 그대로 동작하게 해요 |
| Yahoo 분기 실적이 비어 있거나 전년 분기가 없어요 | 중간 | 줄 단위로 "데이터 없음"을 표시하고 블록 전체는 유지해요 |
| 후보가 너무 많아 다시 막막해져요 | 중간 | 재생성 후 3개 충족 수를 세어 보고, 많으면 다음 단계를 사용자와 정해요. 임의로 기준을 바꾸지 않아요 |
| 문구가 판정이나 추천처럼 읽혀요 | 높음 | 문장은 고정 규칙으로 만들고, 금지 표현 테스트를 추가해요 |
