# 관점 패널

입력: `$ARGUMENTS` — 첫 단어가 종목 코드, 나머지는 사용자가 특히 궁금한 점(없을 수 있어요).

투자 권유가 아니라 판단 재료를 만드는 일이에요. 사용자에게는 한국어 해요체로 말해요.

## 1. 브리프 만들기

1. 종목 코드를 대문자로 바꾸고 `^[A-Z][A-Z0-9.\-]{0,9}$` 형식인지 확인해요. 아니면 멈추고 알려요.
2. `cd backend && .venv/bin/python -m scripts.panel_brief <종목>` 을 실행해요. 마지막 줄이 브리프 파일 경로예요.
   - 서버에 연결하지 못하면 `cd backend && uvicorn app.main:app --port 8000` 으로 서버를 켜야 한다고 알리고 멈춰요.
   - 브리프 끝의 "못 가져온 데이터"에 항목이 있으면 기억해 두고 마지막 보고에 적어요.

## 2. 다섯 관점을 동시에 부르기

한 메시지 안에서 Agent 도구를 다섯 번 호출해 병렬로 돌려요:
`panel-value`, `panel-growth`, `panel-macro`, `panel-skeptic`, `panel-technical`.

각 에이전트에 주는 프롬프트:

```
종목: <종목>
브리프: <브리프 절대 경로>
사용자가 특히 궁금한 점: <있으면 그대로, 없으면 "없음">
.claude/panel/rules.md 의 규칙과 형식대로 답해 주세요.
```

## 3. 종합하기

다섯 답변을 받은 뒤, 직접 브리프와 대조해 숫자가 틀린 인용이 있으면 바로잡고(어느 관점의 어떤 숫자였는지 밝혀요), 아래 형식으로 정리해요.

```
# <종목> 관점 패널 — <날짜>

> 다섯 관점이 같은 데이터(stock-scout, <브리프 날짜>)를 각자 읽은 결과예요. 투자 권유가 아니라 판단 재료예요.

## 관점별 한 줄
| 관점 | 한 줄로 |
(5행)

## 관점들이 같이 짚은 것
- 둘 이상의 관점이 같은 숫자나 사실을 강점 또는 걱정거리로 짚은 것

## 관점이 갈리는 지점
| 쟁점 | 이렇게 읽는 쪽 | 저렇게 읽는 쪽 | 갈림을 풀어 줄 자료 |
(2~4행. 예: 높은 PSR — 성장: 성장률 대비 정당 / 회의론: 기대 과열 / 다음 분기 매출 성장률)

## <사용자가 궁금한 점이 있었다면> 그 질문에 대한 관점별 답
- 관점마다 한두 문장

## 다음에 직접 확인해 볼 것
- 관점들이 "더 확인하고 싶은 것"으로 꼽은 것 중 겹치거나 중요한 3~5개, 어디서 보는지 포함

## 관점별 전문
(다섯 답변을 그대로 붙여요)

---
데이터 한계: <못 가져온 데이터, 스냅샷 날짜 등>
```

4. 종합한 내용을 `backend/data/panel/<종목>-<날짜>-panel.md`에 저장해요(이 폴더는 git에 올라가지 않아요).
5. 사용자에게는 "관점별 한 줄", "관점이 갈리는 지점", "다음에 직접 확인해 볼 것"만 보여 주고, 전문은 저장한 파일 경로로 안내해요.

## 하지 말 것

- 다섯 관점을 하나의 "종합 점수"나 "결론: 매수/관망" 같은 판정으로 합치지 않아요.
- 관점 답변을 고쳐서 의견을 비슷하게 맞추지 않아요. 숫자 오류만 바로잡아요.
